How a review goes

  1. A review is requested

    It lands in your inbox, directly or through a team, with CI, size and a risk estimate on the row. You get a notification when it's requested again.

  2. It's checked out on its own

    Each pull request gets a git worktree next to a shared clone, so Claude reads real files, not just the diff.

  3. Claude Code reads it

    It checks every claim in the description against the code and ranks the findings by severity. With auto-analyze on, this happens before you open it.

  4. You read the change

    Section by section, with a line on what each one does. Ask about anything in the chat as you go.

  5. You approve, and mean it

    Post the review to GitHub with the findings you picked as line comments, or request changes.

Does the code do what the description says?

Each claim is marked as matching, partly implemented, or contradicted by the code. When one doesn't hold, you get the reason and the exact lines.

Ask about the line you're on

The chat knows which finding, section or file you're looking at, and Claude can read the whole repository to answer.

How would you fix the double charge?

Take a short lock on the key before charging: SET idem:lock:{key} NX EX 30 in store.ts:19. A second request that can't get the lock waits for the first response instead of charging again.

What it leaves out

BetterLGTM runs on your machine with the gh and claude you've already signed in to.

  • −No An account and a serverIt talks to GitHub through your gh and to Claude through your claude. Your code and tokens never pass through us.
  • −No Touching your working copyEach pull request has its own worktree. The branch you're on stays exactly as you left it.
  • −No Write accessClaude Code can read, search and look at git history. It can't edit files, run other commands, or comment on GitHub.
  • +The source, MIT licensedRead it, file an issue, or send a pull request on GitHub.

Questions

What does it cost?

The app is free and MIT licensed. Analyses use your Claude Code plan or API usage, and the status bar shows the tokens each pull request used. Auto-analyze is off by default for that reason.

Where does my code go?

Claude reads it from a local worktree through your own claude, the same as when you use Claude Code yourself. BetterLGTM has no server and never sees your tokens.

Can Claude change my code or post on GitHub?

No. It can only read, search and run read-only git commands like git log and git diff. Reviews are posted by the app, through your gh, when you press Submit.

Does it follow our review guidelines?

Yes. It reads a repository's REVIEW.md or the review section of CONTRIBUTING.md and says which file it used. You can add your own instructions, globally or per repository, in Settings.

Where is everything stored?

Clones and worktrees live in ~/.betterlgtm, and analyses, chats and settings in the app's own storage. You can move the folder or clear everything from Settings.

Can I build it myself?

Yes. You need Rust, Node.js 22 and the Tauri prerequisites, then npm install and npm run tauri dev. See CONTRIBUTING.md.
